# ヒキヨミ方式 v2

## 原則

ヒキヨミは、暦上の事実をそのまま勝敗予測へ変換しません。まず複数方式で共通利用できる中間指標へ変換し、その後に総合スロ運、引き運、相性傾向、立ち回りテーマ、注意ポイントへ統合します。

利用者へ点数表示する項目は「総合スロ運」と「引き運」だけです。本人の能力や精神状態を測定していないため、「台選び運」「流れ運」「冷静さ運」という名称と点数表示は使用しません。

## 中間指標

- activity: 行動開始のしやすさ
- judgment: 選択基準の安定
- continuity: 継続性
- adaptability: 変化への対応
- caution: 確認を増やす必要性
- impulseControl: 区切りを置く必要性
- concentration: 集中の維持
- switching: 切替のしやすさ

これらは占い結果を組み立てる内部指標であり、利用者の実際の能力、性格、心理状態を測定した値ではありません。

## 現在のV2基盤

現段階では、以下を有効化しています。

1. 日付の六十干支
2. 日干・日支の構造
3. 生年月日と対象日の縮約数
4. 任意の出生時刻を十二支の時刻区分へ変換
5. ユーザー・対象日・秘密値による±2点以内の決定論的補正
6. 出生日と対象日の60日周期上の距離
7. 本命数と対象日数の周期上の距離
8. 中間指標から総合点、引き運、相性傾向、テーマ、注意ポイントへの統合

暦の構造は公的資料に基づきますが、そこから中間指標や表示内容をどう変換するかはヒキヨミ独自規則です。伝統占術の普遍的事実として扱いません。

## 表示内容への統合

- 総合スロ運: 4系統の内部ガイダンスを重み付きで統合
- 引き運: activity、adaptability、concentration、switching
- 相性のよい機種タイプ: 最も強く出た内部ガイダンスから選択
- 今日の立ち回りテーマ: 最も強く出た内部ガイダンスを文章化
- 今日の注意ポイント: 最も弱く出た内部ガイダンスを文章化
- 相性メーカー: 生年月日、対象日、暦情報、総合点から2社を決定論的に選択

総合点には、60日周期上の距離、数秘上の距離、日干・日支の関係を小幅に加えます。この工程は `FINAL-SCORE-MAP-001` として追跡します。

ラッキー末尾、数字、色、アイテム、機種タイプ、時刻、テーマ、注意ポイントは、確定済みの暦情報と内部ガイダンスから決定論的に導出し、`LUCKY-DERIVATION-001` として追跡します。メーカー候補の導出は `MANUFACTURER-DERIVATION-001` として追跡します。

相性メーカーは、実際の設定状況、設置機種、勝率、推奨機種を示しません。メーカー各社との提携・協賛関係もありません。

## 鑑定内の一致度と判断の分岐

内部ガイダンスごとに、元になった中間指標の開きを計測します。指標同士の開きが小さい場合は鑑定内の一致度が高く、大きい場合は「判断が分かれている」として情報を残します。

結果には次を保存します。

- confidence
- consensus
- mainFactors
- conflicts
- sourceRuleIds
- sourceIds

`confidence` と `consensus` は占い内部の状態を示す値です。勝率、的中確率、科学的信頼度ではありません。画面上では「鑑定内の参考度」「鑑定内の一致度」と明示します。

## 出生時刻

出生時刻は任意です。不明な場合は補正を付けず、減点もしません。分かる場合のみ時支を計算し、補助的な個人化へ使います。

## Geminiの役割

Geminiは点数計算を行いません。コードで確定した総合点、引き運、相性傾向、相性メーカー、ラッキー要素、立ち回りテーマ、注意ポイント、主因、判断の分岐を日本語の鑑定文へ整形するだけです。

Geminiへ送信しない情報:

- LINEユーザーID
- 生年月日
- 出生時刻
- 秘密値
- 画面へ表示しない内部ガイダンス値

Geminiへ送る情報は匿名化済みの公開結果だけです。JSON Schemaによる構造化出力を要求し、危険表現が含まれる場合、API障害時、タイムアウト時、JSON不正時はコード内の鑑定文へ切り替えます。

## 追跡可能性

各寄与は以下を保持します。

- ruleId
- kind
- metric
- delta
- basis
- sourceIds

これにより、どの規則がどの指標を何点動かし、最終結果へどう統合されたかを後から逆引きできます。
